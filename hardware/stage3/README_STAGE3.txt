FROST hardware optimization: stage 3 verified checkpoint
======================================================

Read results/stage3_summary.json and its two CSV companions for the completed
run values. All numbers are parsed from actual tool reports. There are no
placeholder resource, frequency, power, energy or accuracy entries.

Scope
-----
This is a fixed-coefficient rank-2 score-to-weighted-value attention kernel,
with 16 keys, 16 value channels, 16 FSM states, 16 burn-in updates and L=64.
The score and value ports are signed 16-bit with 10 fractional bits; output
ports are signed 32-bit with 10 fractional bits. The implementation retains
32 xorshift32 sources, the original 8-bit CDF tables and 22-bit accumulators.
One tile comprises 16 queries sharing a 16 x 16 value matrix.

It is not a four-block Transformer, a whole-image inference measurement, or
the rank-16 FROST-LT reconstruction algorithm. The historical provenance file
inputs/stage2_candidate_provenance.json describes the earlier L=256 software
candidate; the current measured configuration is L=64. Its recorded accuracy
limitations are not erased by these hardware optimizations. No new numerical
accuracy-parity claim is made in this stage.

Target-specific RTL
-------------------
Original: l64c, retained for a direct optimization comparison.
FPGA: perm. Prefix sorting decisions, permutation/order register aliasing,
and a monotone terminal CDF decoder preserve inferred distributed value RAM.
Standard cell: hot_reuse. In addition to prefix decisions and permutation
aliasing, dead score storage is reused for thresholds and a shared one-hot
value selector replaces independent variable-index selection trees.
These are two distinct implementations, not one netlist with interchangeable
FPGA resource counts and standard-cell power values.

Controls
--------
fp32_1 and fp32_4 use binary32 arithmetic with 1 or 4 FMA lanes and an
exponential lookup table; their accurate label is FP32-LUT.
fx16 uses a 17-bit exponential LUT with 16 fractional bits, four reused
multipliers, a 38-bit accumulation path and an integer reciprocal.
These are numerical hardware controls, not stochastic-computing baselines.
The manuscript's software SC reconstruction controls have not yet been
implemented or measured in this hardware flow. No label substitution is valid.

FPGA methodology
----------------
Yosys 0.33 (2584903a060), nextpnr-ecp5 0.6-3build5, LFE5U-85F,
CABGA381, speed grade 6. Every design was routed with seeds 1, 2 and 3 and
an 8-MHz clock constraint. Report TRELLIS_COMB, TRELLIS_FF, MULT18X18D,
DP16KD and TRELLIS_RAMW separately; TRELLIS_COMB is not Yosys LUT4 count.
The reported timing frequencies are internal register timing estimates of
these routed designs, not a frequency sweep or measured board Fmax.
I/O is unconstrained. No bitstream was tested on a physical board.

Standard-cell power methodology
------------------------------
Yosys/ABC mapping uses Nangate45 typical (1.1 V, 25 degrees C). OpenSTA 3.1.0,
commit 4f8d3ae6bd3da537f8c4e819c2b327545294fd4d, estimates internal, switching
and leakage power from Verilator 5.020 zero-delay gate activity at 15 MHz.
Source archives, the exact binary, build settings and dependency package
hashes are retained under ../toolchain. All relevant external pins in the
flattened netlist are VCD-annotated; reports show zero unannotated pins.
Sequential internal pins excluded by OpenSTA are not claimed as annotated.

The activity window is the first frozen evaluation tile, including value and
score loading, burn-in, numerical conversion and output transfer. Reset and
32 seed-initialization cycles precede the window. Timestamp resolution is 1 ps.
All designs use the same score/value tile. FROST is run with seeds 4004,
5005 and 6006; deterministic controls have one run. These three-seed SDs
describe stream variability on one tile, not input-population uncertainty.

Power is a mapped standard-cell, pre-layout estimate. It omits routed wire
parasitics, inserted clock-tree cost, physical glitches, pads, external memory,
host and board costs. The 15-MHz ASIC analysis is independent of the 8-MHz
FPGA comparison. Do not multiply an ASIC power by an FPGA latency.
Energy per tile in microjoules = power in watts x cycles / frequency in MHz.

Verification
------------
The prior stage checked 153600 normal words plus 3072 corner words per RTL
candidate and identical public-port cycle counts. Those records are copied
to previous_stage_evidence/ and retain their original stage-2 identity.
In stage 3, every power waveform is generated by a mapped standard-cell
simulator and compared to RTL on 16 queries x 16 output words. Each FROST
variant checks 768 gate words across three seeds; each numerical control
checks 256 words. Both output values and query cycle counts must match.
This is simulation evidence, not formal equivalence or full-model validation.
The original l64c and numerical-control power numbers reproduce the archived
results, providing a check on the restored toolchain and activity time units.

Reproduction
------------
Unpack the archive and keep stage3/ and toolchain/ as sibling directories.
Use an Ubuntu 24.04-compatible x86-64 runtime with Python 3/numpy, g++, make,
dpkg-deb and zlib development files. From stage3/:

  python3 source/restore_stage3_tools.py

This extracts recorded packages locally. The Ubuntu nextpnr binary requires
its chip database at /usr/share/nextpnr; the restoration script creates a
symlink only if it does not exist. If this path cannot be created, install the
recorded nextpnr/chipdb packages using the machine's normal package manager.
To rebuild the archived OpenSTA source instead of using the archived binary:

  python3 source/restore_stage3_tools.py --rebuild-opensta

Build the public-port RTL models and, if needed, repeat full stage-2 checks:

  python3 source/stage2_flow.py build l64c perm hot_reuse fx16 fp32_1 fp32_4
  python3 source/stage2_verify.py l64c perm hot_reuse

Repeat mapping and routing:

  python3 source/stage2_flow.py ecp5 l64c perm fx16 fp32_1 fp32_4
  python3 source/stage3_route.py
  python3 source/stage2_flow.py asic l64c hot_reuse fx16 fp32_1 fp32_4
  python3 source/stage3_flatten.py

Generate gate activity and estimate power:

  python3 source/stage3_exec.py python3 source/build_gate_simulators.py --build build/gate --designs l64c hot_reuse fx16 fp32_1 fp32_4
  python3 source/stage3_power.py wave l64c hot_reuse fx16 fp32_1 fp32_4
  python3 source/stage3_power.py sta l64c hot_reuse fx16 fp32_1 fp32_4
  python3 source/stage3_aggregate.py

Archived raw VCD gzip files can be analysed directly without rebuilding the
gate simulators. Do not change or truncate their activity window. All wave
manifests, source and netlist hashes, route reports and power logs are retained.
Absolute paths in run records identify the original workspace; scripts derive
new work paths relative to their own location when re-executed elsewhere.
